# 故障排查

简体中文 | [English](troubleshooting.en.md)

以下区分可复现的工程问题和通用排查项；不要把所有可能原因都写成目标项目已发生的问题。

| 症状                                          | 可能原因                                                 | 检查方法                                                                                                     | 修复方向                                                                                                                 |
| --------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| Pages 白屏，入口 JS/CSS 404                   | base 为 `/`，站点实际挂载于 `/<repo>/`                   | 检查发布 HTML 中的 URL、Network、Pages URL                                                                   | 用真实 `base_path` 重建并发布                                                                                            |
| 资源 HTTP 200，但 JS MIME 报错/解析到 `<`     | dev/preview HTML fallback；旧 preview base；路径写错     | 检查 Content-Type 和响应前几十字节，而非只看状态码                                                           | build/preview 使用同一 base 并重启服务，修复路径；线上重新构建                                                           |
| WGSL/GLSL fetch 失败或得到 HTML               | 源码文件没有进入产物；根绝对路径                         | 打开 shader 最终 URL、检查构建目录和实际文本；fetch.text 不要求特定 shader MIME，未知扩展可能无 Content-Type | Vite `?raw` 或显式静态资源复制和 base-aware URL；保留现有 loader                                                         |
| 模型存在但纹理缺失                            | glTF 外部资源相对路径、大小写、未复制                    | 检查模型实际请求 URL 及其贴图请求                                                                            | 按模型目录关系完整部署；修正大小写和资源根                                                                               |
| WASM 编译报错                                 | HTML/404 当成 WASM；错误 MIME                            | 检查响应为 `application/wasm`，二进制 magic 为 `00 61 73 6d`                                                 | 修正 URL/静态输出；仅在 MIME 不满足 streaming 条件时用 ArrayBuffer 实例化回退，并保留错误反馈                            |
| worker 或 WASM glue 本地正常、线上失败        | 内部根路径/跨域 URL；动态路径未被重写                    | 从 glue/worker 入口追踪 Network，检查 CORS                                                                   | 根据工具链设置 locateFile、worker URL 与资源复制；不依赖 dev server 的代理                                               |
| `navigator.gpu` 不存在                        | 不安全上下文或浏览器/系统不支持                          | 检查 HTTPS/localhost 和能力检测结果                                                                          | 显示明确兼容性提示；不要通过关闭浏览器安全策略部署                                                                       |
| requestAdapter 返回 null / requestDevice 失败 | 硬件、驱动、浏览器 blocklist、请求了过多 features/limits | 区分 API 缺失、adapter 缺失与 device 异常                                                                    | 减少不必要特性请求；提示用户检查硬件加速和驱动，保留可诊断错误                                                           |
| shader/pipeline 初始化失败                    | WGSL 错误、layout 不一致、usage 或 size 不合法           | getCompilationInfo、异步 pipeline rejection、error scope、Console                                            | 修复首次错误；不能用禁用 validation 掩盖                                                                                 |
| 刷新/resize 后黑屏                            | swapchain/context、depth 贴图尺寸不一致或 device lost    | 观察 canvas backing size、GPU 错误和 lost promise                                                            | 按设备上限重建 depth；停止失败帧循环，显示恢复入口                                                                       |
| GPU 可见数偶发错误或越界                      | atomic 没逐帧归零；跨 workgroup reset；布局不对          | 回读真实 args/索引，与独立参考比较，含 0/N 及连续帧                                                          | reset 在 dispatch 前；compute 和 graphics 分 pass；storage/indirect/COPY flags 正确，按 WGSL 对齐布局                    |
| GPU profiling 不可用                          | timestamp-query 为可选特性                               | 检查 adapter/device features，而非假设支持                                                                   | 非必需则禁用并显示未采集/不支持；FPS/CPU 帧时间不能冒充 GPU 时间                                                         |
| configure-pages 404 / Get Pages site failed   | Source 尚未设为 Actions；权限不够；仓库不可访问          | 读取 Pages API 与本次 workflow 日志                                                                          | 启用 Pages，核实仓库权限/套餐；不在 workflow 中硬塞 PAT                                                                  |
| deploy-pages 权限或 OIDC 错误                 | 缺 pages/id-token write，environment 保护或分支不允许    | 查看失败 job/step、permissions、environment 规则                                                             | 在 deploy job 最小配置必要权限；由有权限者处理保护要求                                                                   |
| Actions 等待 artifact 或部署旧代码            | artifact 路径错、缺 needs、查看了错误 run                | 对照 SHA、run、上传 job 与 deploy job                                                                        | 上传包含 index.html 的正确目录，建立依赖，跟踪同一 SHA                                                                   |
| npm build 在 CI 失败                          | Node 版本、大小写、缺 devDependencies、漏锁文件          | 对照 package engines、lockfile、Linux 日志，干净安装重现                                                     | 保持 Node/包管理器一致，修源代码，不把 `continue-on-error` 当修复                                                        |
| npm ci 报平台可选包不在 lockfile              | 重用已有 node_modules 生成了不完整锁；npm bug            | 在隔离干净目录重建锁并再次 npm ci，对照缺失包名                                                              | 保留用户修改后只清理/移走生成依赖，重新生成并审查锁；不能只改 CI 为 npm install                                          |
| npm install 长期解析无关可选 peer 树          | npm/构建工具可选 peer 解析问题或网络                     | 查看 npm 日志、registry、Node/npm 版本                                                                       | 先定位网络/版本；若采用 legacy-peer-deps 必须在项目 .npmrc 固定并审查必需 peer，保证 npm ci 一致；不要对所有项目默认启用 |
| SharedArrayBuffer / WASM threads 失败         | 页面未 crossOriginIsolated，缺 COOP/COEP                 | 检查 crossOriginIsolated、Network headers、工具链线程要求                                                    | Pages 不能自由设置这些 headers；使用单线程版本或改托管。Service worker 隔离有首次加载和资源限制，须单独评估验证          |
| HTTP 成功但浏览器自动化超时                   | 工具连接、AX/DOM 通道、页面进程问题                      | 用工具支持的 DOM/AX/截图或普通浏览器核对                                                                     | 不重复无界等待；不能恢复时写清线上 GPU/Console 未验证，保留本地和 HTTP 证据                                              |

实际部署排查的高价值经验：验证生产子路径而非只测 `/`；检查 HTTP 内容而非只看 200；在 Windows 与 Linux 间检查锁文件和大小写。其余项按目标项目触发，不引入未被需要的 profiler、WASM 或 service worker。

依据：[npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/)、[npm 可选依赖问题 #4828](https://github.com/npm/cli/issues/4828)、[WebGPU 规范](https://www.w3.org/TR/webgpu/)、[跨源隔离](https://web.dev/articles/cross-origin-isolation-guide)。
